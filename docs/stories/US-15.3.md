## Story

As a team, we want a last check of every deliverable against the briefs so that nothing is missing at submission.

## What was done

1. **Walked both deliverable lists in Appendix B** of `docs/plan/LUE_Development_Plan_v1.1.md` and ticked every item against an actual file or confirmed deliverable in the repository.  The completed checklist is saved in `docs/evidence/us-15.3/01_appendix_b_checklist.md`.
2. **Created `scripts/package_submission.py`** — an offline script that:
   - Collects every Phase 2 and Phase 3 deliverable file by its documented path.
   - Checks each file exists (or records it as a human deliverable, e.g. PBIX, presentation).
   - Prints a compact submission manifest: file path, format, size, producing story.
   - Exits 0 when all code deliverables are present, 1 otherwise.
3. **Added `package` target to `Makefile`**: `$(PYTHON) scripts/package_submission.py`.
4. **Created the git tag** `phase3-submission` on this branch's HEAD commit to mark the release candidate.
5. **Verified PBIX opens** — `docs/powerbi/LUE_Dashboard.pbix` opened in Power BI Desktop on the demo machine; all three pages load; the instructions are in `docs/powerbi/README.md`.
6. **Recorded submission confirmation** placeholder in `docs/evidence/us-15.3/02_submission_confirmation.md`.

## Decisions

- The git tag `phase3-submission` is placed on the HEAD of `user-story-13-15` before the branch is merged to `main`; after merging, the tag will be re-pointed to the merge commit.
- The PBIX and the presentation (PPT/Google Slides) are human deliverables — the packaging script records them as `MANUAL` and does not fail on their absence; it only fails if a code deliverable (SQL, Python, PDF generated by code) is missing.
- Submission confirmation (`02_submission_confirmation.md`) is a placeholder; the team fills in the LMS submission link and timestamp after uploading.
