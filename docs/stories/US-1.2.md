## Story

As a data modeler, I want all 13 dimensions deployed with surrogate keys, natural keys and constraints, so that
facts and SCD logic have a sound foundation.

## What was done

1. `sql/10_ddl/01_dimensions.sql`: the dimension section of the frozen `docs/phase1/sql/physical_model.sql`, copied
   unchanged except for the additions below. All 13 dimensions are in `lue_dw`, with their special members.
2. Surrogate keys are `GENERATED BY DEFAULT AS IDENTITY` in 12 dimensions (D6). The special members -1 and -2 are
   inserted with explicit keys, which does not move the identity sequence, so the first loaded member gets key 1.
   No sequence restart is needed; the tests prove it.
3. The four SCD Type 2 dimensions (`dim_unit`, `dim_tenant`, `dim_maintenance_category`, `dim_vendor`) keep the
   pack's `UNIQUE (natural key, effective_from)` and gain `ck_<dim>_effective_range` (`effective_to > effective_from`)
   and the partial unique index `uq_<dim>_one_current` (one `is_current` row per natural key).
4. `scripts/db_deploy.py` runs every file in `sql/10_ddl/` as `lue_etl` in one transaction; a failure changes
   nothing. US-1.3 and US-1.5 add their files to the same folder.
5. `scripts/check_contract.py` compares `sql/10_ddl` with the frozen DDL (columns, types, NULL rules, constraints,
   special members, indexes) and is part of `make test`, so CI fails on any drift from the Phase 1 design. It was
   checked against six deliberate mistakes (changed type, dropped NOT NULL, renamed column, missing constraint,
   changed special member, extra index); it caught all six.
6. `scripts/test_dimensions.py`: 27 acceptance checks, run as `lue_etl`.
7. `scripts/test_db_setup.py` (US-1.1) now prints a clear FAIL instead of a traceback when PostgreSQL is not running.

## Decisions and deviations

- **`dim_date` keeps its `YYYYMMDD` key** (pack design; loaded by US-1.4), so it has no identity column and no
  lineage columns, as in the pack.
- **`dim_request_flags` has no special members**, as in the pack (its generator deliberately leaves them out): every
  request has the three flags, so all 8 combinations always exist. The plan's US-1.4 says "8 rows plus the Unknown
  member", which cannot fit: the three flags are NOT NULL and each combination is unique. Recorded for US-1.4.
- **Special member -2 exists in 12 dimensions**, as in the pack (the plan text mentions it only for tenant; facts
  use -2 in several places, for example `resolved_date_key = -2` for open requests).
- **The pack's 38 foreign-key and filter indexes are not deployed**: none are on dimensions, and D20 keeps them out
  of the Phase 3 baseline. The new partial unique indexes enforce a rule (like a unique constraint), so they are
  part of the baseline.
- **`key_is_special()` is created as `lue_dw.key_is_special()`**, not unqualified as in the pack.
- **Re-runs** skip existing tables. Changing a table's definition later needs the reset script (US-1.5).
