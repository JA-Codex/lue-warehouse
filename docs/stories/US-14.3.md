## Story

As a presenter, I want a structured slide deck and a rehearsed demo script so that the team can deliver a coherent 20-minute presentation without reading from notes.

## What was done

1. **Slide outline** (`docs/evidence/us-14.3/01_presentation_outline.md`) — 13 slides covering the full project arc: business problem, design decisions, architecture, ETL pipeline, data quality, SCD example, performance, dashboard walkthrough, five insights, lessons learned and Q&A.
2. **Demo script** (`docs/evidence/us-14.3/02_demo_script.md`) — step-by-step narration for the live demo section (slides 8–10), covering: `make rebuild`, the quarantined row in the quality report, the SCD2 history query, the EXPLAIN ANALYZE benchmark, and the dashboard drill-through.
3. **Rehearsal notes** (`docs/evidence/us-14.3/03_rehearsal_notes.md`) — timing per section, speaker assignments, known risks (database not loaded on demo machine — mitigation: use the PDF export and the offline script outputs), and backup plan (screenshots of all key outputs in the slide deck).

## Decisions

- The slide deck itself is a human deliverable (PowerPoint / Google Slides); only the outline and script are committed to the repository.
- The demo script uses `make rebuild` as the entry point because it is the single command that runs the full pipeline — this is the most impressive demonstration of the project's reproducibility.
- Backup screenshots are embedded in the slide deck (not committed) so the presentation can proceed even if the database is not available on the demo machine.
