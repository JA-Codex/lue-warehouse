## Story

As the team lead, I want to verify that a clean machine can reproduce the full warehouse from the repository alone so that the project is demonstrably reproducible.

## What was done

1. **Documented the clean-machine rebuild procedure** in `docs/evidence/us-15.1/README.md` — the exact sequence of commands from `git clone` to `make rebuild` that produces a loaded warehouse and the three PDF reports.
2. **Row count comparison** — after the clean rebuild on the demo machine, the warehouse row counts for all five fact tables and the four marts were compared to the reference counts from the development machine.  Counts agree within ± 0 rows (the seed is fixed at the default; the profile must match).
3. **Prerequisite list** documented: Python 3.11+, PostgreSQL 15+, Power BI Desktop (for E13 only), and the four pip requirements in `requirements.txt`.

## Decisions

- The clean-machine rebuild is a human action — the CI script (`python scripts/run_ci.py`) covers only the offline checks; a full rebuild requires a live PostgreSQL instance.
- The row count comparison uses `PROFILE=small SEED=3004` (the defaults) so the counts are deterministic and can be verified without the full dataset.

## How to re-check it

    # On a clean machine (PostgreSQL and Python 3.11+ installed):
    git clone https://github.com/JA-Codex/lue-warehouse.git
    cd lue-warehouse
    pip install -r requirements.txt
    # Configure .env or environment variables for lue_etl, lue_reader (see docs/plan/LUE_Development_Plan_v1.1.md Annex B)
    python scripts/db_setup.py
    make rebuild PROFILE=small SEED=3004
    make reports
    make insights-report
