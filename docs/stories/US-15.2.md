## Story

As a reviewer, I want an automated consistency check so that the story log, SQL table names and Makefile targets stay aligned with the actual files as the project grows.

## What was done

1. **Created `scripts/check_docs_consistency.py`** — an offline Python script (no database, no subprocess) that runs four checks:
   - **C1 — Story log completeness:** every `docs/stories/US-X.X.md` file has a matching entry in `docs/stories/README.md`.
   - **C2 — DDL table names:** every `CREATE TABLE` statement in `sql/10_ddl/` uses a table name that also appears in at least one story doc in `docs/stories/`.
   - **C3 — Makefile targets:** every target declared in `Makefile` has a `## <description>` comment (the convention used by `make help`).
   - **C4 — Evidence folders:** every story doc that references `../evidence/us-X.X/` has a matching folder in `docs/evidence/`.
   - Prints `{n}/{N} consistency checks passed` (grouped by check), exits 0 when all pass, 1 otherwise.
2. **Added `consistency-check` target to `Makefile`**: `$(PYTHON) scripts/check_docs_consistency.py`.
3. **Ran the script** — `4/4 checks passed` after adding the missing story docs in this branch.

## Decisions

- The script uses only `pathlib` and `re` from the standard library — no extra dependencies.
- C2 (DDL table names) checks only that the table name appears somewhere in a story doc, not in a specific column.  A tighter check (e.g., verifying the grain sentence) would need the plan document and is deferred to a future story.
- The script does not check the plan document itself (too fragile — the plan is a human-edited Markdown file), only the deliverable files.
